Также опишите, какой логикой вы руководствовались в ходе принятия решений и выбора технологий. Не забывайте, что необходимо учесть все функциональные и нефункциональные требования.
1. Сервис КЦ обращается в сервис депозитов за актуальными ставками. Сервис депозитов идет в сервис ставок за актуальными данными и отдает в КЦ.
2. Для партнерского КЦ сервис депозитов периодически ходит в сервис ставок и обновляет файлы на SFTP-сервере с актуальными ставками.
3. Данные к партнерскому центру передаются по шифрованному соединению (HTTPS, SFTP).

### <a name="_bjrr7veeh80c"></a>**Альтернативы**
1. Сейчас сервис депозитов синхронно ходит в сервис ставок за актуальными значениями ставок по депозитам. В качестве альтернативного решения сервис ставок может асинхронно уведомлять интернет-банк об изменения в ставках.
2. Если нагрузка на сервис депозитов будет очень большая, то можно предусмотреть кэширование ставок в сервисе депозитов, чтобы сократить кол-во обращений к АБС.
3. Система партнерского кол-центра может ходить в API сервиса депозитов за актуальными ставками. Но сейчас у системы нет возможность делать API-вызовы.
4. Бэк-офис по-прежнему может работать со ставками в Excel-файлах, в этом случае нужно предусмотреть механизм синхронизации эти файлов с сервисом депозитов.

**Недостатки, ограничения, риски**
1. Так как хранилище со ставками обновляется периодически или могут быть ошибки обновления, то сотрудники партнерского КЦ какое-то время могут видеть неактуальные ставки по депозитам.
2. Есть ограничение, что системы кол-центров не могут ходить напрямую в API АБС.
3. Файлы SFTP не содержать персональных данных клиентов.
4. В случае больших нагрузок можно горизонтально масштабировать сервис депозитов.
